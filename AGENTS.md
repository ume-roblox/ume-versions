# AGENTS.md

Guide for AI agents working in this repo.

## What this is

ume-versions is the ume family's public front page (`README.md`: the family table, how the pieces fit together) and the home of the version badges every other README shows. It holds no code.

## Read first

`.claude/rules/family/*`: the ume family, agent files, working style, docs and releases. `family/releases.md` says when a badge changes.

## Repo map

| Path | What |
| --- | --- |
| `README.md` | The family's front page |
| `src/<name>.json` | One [shields.io endpoint](https://shields.io/badges/endpoint-badge) per repo: `framework.json` (ume), `gui.json` (ume-gui), `lsp.json` (ume-lsp), `vscode-extension.json` (ume-vscode), `roblox-extension.json` (ume-rbx), `sync.json` (ume-sync) |
| `docs/assets/` | The README's SVG panels, generated |

## Changing things

- **A badge:** set only `message` to the new version, keep the rest of the file as it is, and commit as `Bump the <label> badge to <version>` (one commit may bump several: `Bump four badges to the latest releases`). Only when the user asks, after that repo's release.
- **The README art** is generated by `<art-tools>/images/ume-family-readme/generate.mjs`: change the generator and run it with this repo's path; never edit the SVGs by hand. Draw it again when a repo joins the family or its description changes.
- **The family table** changes when a repo joins or is renamed; the same change goes into `.claude/rules/family/family.md` in every repo (`family/family.md`, Shared files).

## Working across repos

Every other repo's `release` skill ends by asking for its badge here. Don't change a sibling from here unless asked.
