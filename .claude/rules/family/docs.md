# Docs

*Shared rule: an identical copy sits in `.claude/rules/family/` of every ume repo. Change all copies together (`family/family.md`).*

How every ume repo writes for people. The repo's own docs rule, where it has one, maps each kind of change to the doc it updates.

- **Tone:** plain, short, factual. Describe what exists. Planned work is labelled as planned, never written as done.
- **README.md** is the front page: what the repo is, its SVG panels, a quick start, links into `docs/`. No long reference material: that goes in `docs/`. Versions show as badges in ume-versions, not in the text. Don't rewrite a README unless the user asks; when a change makes a line wrong, fix that line.
- **SVG panels** live in `docs/assets/` as `-light.svg` / `-dark.svg` pairs, shown with `<picture>` and `prefers-color-scheme`, each with an `alt` that is a full sentence. Most are generated by `A:\Assets\__claude\images\<repo>-readme\generate.mjs` (`ume-family-readme` for ume-versions, `ume-org-readme` for .github-private): change the generator and run it again, never edit a generated SVG by hand. ume-sync draws its panels by hand (its docs rule).
- **`docs/`** is one topic per file. Update the matching doc in the same change as the behaviour.
- **Unit READMEs.** In the Luau repos, every module, library, tool or engine unit is described in its own `_meta/README.md` (`luau/readme.md`). `docs/` explains how the pieces fit together; it links to unit READMEs instead of repeating them.
- **Words:** ume-sync syncs projects into Studio. Say "Rojo" only for the project file format (`*.project.json`, `*.model.json`), which ume-sync reads unchanged.
- **Agent files** (`AGENTS.md`, `CLAUDE.md`, `.claude/`) follow `family/family.md`.
- **Decisions** that are hard to reverse go in `docs/adr/NNNN-title.md` in repos that keep ADRs. Don't edit an accepted ADR's decision: add a dated note, or supersede it with a new ADR.
- **No CHANGELOG.md.** Release notes go in the GitHub release (`family/releases.md`).
